# 支持范围与数据流

## 首版支持矩阵

| 部分 | 支持与验证范围 |
| --- | --- |
| 系统 | Windows x64，本地单用户，默认仅监听 127.0.0.1 |
| Python | CPython 3.14 x64；Python 包的精确版本与哈希见 requirements.lock |
| 前端开发 | Node.js 24 或 25，使用 npm ci；普通用户运行预编译前端无需 Node |
| 模型 | DeepSeek 官方、GLM 官方、硅基流动；自定义供应商按配置页支持的协议和能力选择 |
| 文件 | XLS/XLSX、DOCX、Markdown；Office 不需要作为导入依赖安装 |
| 其他系统/Python | 尚未纳入发布验收；文件选择、进程控制和离线二进制有 Windows 专用实现 |

复制源码时不要复制虚拟环境。目标机器安装 Python 3.14 后可运行 `SOPweave.bat --offline`，在本机创建 `.runtime` 并按完整锁文件安装；依赖已就绪后使用 `SOPweave.exe` 启动服务并自动打开浏览器。启动器复用 Windows .NET Framework 4.x，不包含 Python、前端或业务数据；环境配置与安装程序尚未提供。源码的测试样例可放在项目目录；真实用户工作目录由用户选择。

## 在线与离线

模型分析会把用户输入及任务选取的数据发送至用户配置的模型供应商。文件扫描、确定性计算、SQLite 和报告存储在本机。Agents SDK tracing 默认关闭。供应商密钥保存在本机配置数据库，不应随源码分发。

离线依赖介质需要包含与 requirements.lock 匹配的 Windows/Python wheels；前端 dist 和 public/vditor 应完整。AI 模型调用需要可用网络服务，或用户自行配置的本地兼容服务。

## 文件保真与并发

普通表格和文档可读取、修改、导出。含宏、复杂图形、外链、嵌入对象的 Office 文件需要按具体能力检查；修改前应保留原件。文本编辑器保存携带版本号，外部程序已修改文件时返回冲突，用户需重新读取后合并。

## 发布前必备

MIT 许可证、完整源码清单、锁文件、测试结果、离线依赖校验和及第三方声明。源码包不包含 API Key、运行数据库、用户文件或虚拟环境。

## 持久状态与保留

运行、交互、报告目录保存在应用 SQLite；导入/写回进度保存在独立的 `data/tasks.sqlite3`，避免长表格事务锁住进度报告。重启后保留表头确认任务，进行中的导入/写回标记中断供用户检查。已执行的文件操作不会自动重放。

审计快照默认保留。设置 `SOPWEAVE_SNAPSHOT_RETENTION_DAYS` 为正整数才启用按天清理；0 表示保留。备份需覆盖整个 data 目录及用户选择的外部工作目录。

`SOPWEAVE_DATA_DIR` 可指定独立数据目录，相对值以应用目录为基准，隐藏应用工作区同步跟随。`SOPweave.bat --check` 使用临时数据目录验证启动，不修改日常数据。

分析读取默认预算为 200 万单元格，可用 `SOPWEAVE_ANALYSIS_MAX_CELLS` 调整，0 表示不限。超过预算会明确拒绝，不截取部分数据继续计算。编号及文本列保留结构化库中的值，数值转换由具体模型或用户选择的预处理步骤执行。

多文件分析中，选中的文件读取失败会终止计算；按键合并须具备非空唯一关联键（支持组合键），歧义会提示先聚合或补键，避免多对多展开重复金额。
