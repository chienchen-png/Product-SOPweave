# 用户操作说明

适用：Windows x64、CPython 3.14。安装和支持范围以[项目首页](../../README.md)及[支持矩阵](SUPPORT.md)为准。

## 1. 启动

运行环境准备后，在应用目录双击 `SOPweave.exe` 或桌面快捷方式，服务就绪后自动打开默认浏览器。关闭页面不会结束服务，托盘菜单提供“打开 SOPweave”“查看启动日志”和“退出并停止服务”。启动器使用 ASGI 服务，同时提供业务接口与智能体 SSE。[启动器说明](LAUNCHER.md)包含构建与桌面入口设置。

源码首次使用需要 Node.js 24 或 25：先执行 `npm ci --prefix frontend`、`npm run build --prefix frontend`。带有前端构建结果的发布包无需 Node.js。

离线安装按[离线介质说明](OFFLINE.md)准备 Python 和锁定依赖。AI 调用需要访问所配置的模型服务。

端口被占用时运行 `SOPweave.exe --port 8081`。启动器不会关闭占用端口的其他程序。

## 2. 配置模型

1. 打开 AI 配置，新增供应商。
2. 选择 DeepSeek 官方、GLM 官方、硅基流动或自定义供应商。
3. 三家模板自动绑定官方地址和适配方式，只填写自己的 API Key、API 模型标识。
4. 自定义供应商填写名称、URL，使用当前支持的 Chat Completions / Bearer 协议；按服务需要选择思考参数形式。
5. 完成文本、流式、工具调用、工具续接和用量检测后，模型进入可用列表。失败模型仍可在配置页检查与重试。

显示名称与 API 模型标识分别保存。新增、修改、默认和删除同步用于项目聊天及集成应用。官方服务过载时稍后重试，不要把供应商限流当成配置成功。

## 3. 项目聊天

创建项目并选择自己的工作目录，再选择模型、本轮 SOP 和工作模式。SOP 入口位于输入框工具栏、模型与工作模式之间；可以浏览、上传、编辑项目文件，导入数据后进行查询、核对和分析。

SOP 有三种范围：“自动发现”让模型按任务从已授权流程中查找并加载；“指定 SOP”固定一个流程并填写其必填参数；“仅内置流程”不加载“我的 SOP”，但仍保留内置能力与 Office 支撑。选择按项目会话保存，用于下一次发送；运行开始后固定当时的版本，执行中不能切换。

默认工具及按需加载的 Office、数据和分析能力见[Agent 运行时](AGENT_RUNTIME.md)。写入审批、通用程序执行和 SOP 程序规则共同约束操作；选择全自动模式不代表绕过强制规则。

询问、审批在对话中展示，完成答复后继续原任务。浏览器关闭不代表业务操作已经回滚；重新打开后先检查任务状态及输出。

## 4. 自定义财务 SOP

左侧“财务 SOP”页面是 Skill/SOP 的唯一管理入口。设置中的 AI 功能配置只保留模型配置和智能体配置。正常安装默认开放用户 SOP，不需要额外设置环境变量。内置条目保持只读，用户技能通过草稿、预览、确认发布进行管理。

财务 SOP 分为两个标签：“内置 SOP”只展示内置流程、Office 支撑和可视化执行步骤；“用户 SOP”提供发布流程和草稿。顶部右侧始终只有刷新；进入用户 SOP 后，使用内容区的“新增 SOP”菜单选择新建或导入 GitHub / ZIP。

- 从文字或上传的文档创建草稿，选择模型解析需求。
- 检查功能、输入、工具、步骤、追问与执行规则；需要时补充答案、修改并重新生成。
- GitHub/ZIP 导入先选择具体 Skill，查看兼容性和差异；导入脚本不会自动执行。
- 在独立样例环境试运行，检查实际工具证据；需要审批时先确认再继续。
- 用户确认当前预览后才能发布。项目聊天选择已发布版本执行，历史任务绑定实际使用的版本。
- 财务 SOP 页面只展示当前可用流程，并承担查看、编辑、删除、导入和新增；列表和详情不提供“使用此 SOP”跳转。选择某个 SOP 是否用于本轮任务统一在项目对话输入框完成。管理页不提供全局启用/停用按钮。
- 删除 SOP 前先结束使用该 SOP 的任务；有运行、等待审批或等待输入的租约时服务端会拒绝删除。
- 已完成对话可以准备为新 SOP 草稿；不会未经确认直接安装。

## 5. 两个集成应用

**数据核对**：上传依据表与分表，完成字段映射，检查差异，确认允许的修改，再查看结果和报告。

**财务建模**：选择分析目标和模型，核对导入字段、参数及图表，生成报告。报告可以用 Markdown 编辑并导出；Word 导出需要 Pandoc，PDF 使用前端打印流程。

两个应用各自使用隐藏工作区，不要求先创建普通项目。隐藏工作区的模型配置与项目聊天共用供应商适配层。

## 6. 文件与数据

- 结构化业务数据由 SQLite 管理；JSON 用于接口、字段定义和配置。
- `.runtime` 是本机运行环境，复制到另一台电脑后重新生成。
- `data` 包含本机配置、数据库、恢复备份及工作结果；不要上传 GitHub。
- `examples` 是可随源码移动的人工样例；用户工作目录由用户选择。
- 不向别人分发自己的 API Key、数据库或原始财务文件。

需要开发与排错时阅读[架构说明](ARCHITECTURE.md)和[开发指南](../../CONTRIBUTING.md)。

## 7. 工作台、任务恢复与报告

- 首页展示今日 Token、今日 AI 请求、今日运行（成功／失败）及今日应用运行时长。时长为服务启动至关闭的累计值，重叠会话不重复计算。
- Token 趋势支持 7／30 日，排行支持供应商／模型切换；两个图共用日期范围，今日指标不随范围改变。
- 用量从升级后首次启动开始采集，以供应商响应为准；缺失显示“—”或缺失提示，真实零显示 0，旧版本未采集的数据不补算。模型验证、项目聊天、SOP 创作与两个应用的真实模型调用都计入。
- 首页标题栏显示本机实时时钟，按当前电脑时区每秒更新；模型配置从首页移除，通过左侧“设置”进入。
- 一次模型调用计一次请求，多轮工具调用和应用重试分别计数；SDK 内部网络自动重试不拆分。按浏览器时区、调用开始日期归属；删除项目或供应商仍保留全局历史用量。
- 集成应用自动保存目标、文件选择、配置和步骤。出现保存冲突时保留当前输入，先比较，再选择重试或重新加载服务端草稿。
- 修改上游配置或更新导入数据会清理旧计算结果，需重新执行。恢复旧任务结果也会检查数据版本。
- 项目聊天离页后任务继续执行；返回原项目即可从对话历史和当前状态继续处理审批。两个集成应用在各自页面内提示并恢复当前应用任务，不再提供全局任务列表。重新连接不会重新运行工具。
- 两个应用的报告共用 Markdown 编辑器。保存只改变报告说明；差异金额、计算结果和实际写回仍以程序记录为准。
- A1/A2 可选择并确认写回；B/C 先人工复核并修正数据，再重新核对。页面不再把不可自动处理的差异列为自动写回选项。
- 报告保存遇到文件版本冲突时保留编辑，可查看磁盘版本并比较。Word 由后端导出，PDF 通过编辑器“导出 → PDF”进入浏览器打印，选择另存为 PDF。
- 服务端历史不依赖浏览器缓存；“从历史列表移除”只隐藏列表记录，保留报告文件。
